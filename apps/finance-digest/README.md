# finance-digest: the daily Money Hub digest

A daily, **read-only** summary of Money Hub, written into the AI Library and optionally appended to
Notion. Spec: `docs/CONTRACTS.md` §12.18 (module D). Python 3.11+, **standard library only**, plus
the `library` package from `apps/skill-library`. It never moves money, marks bills or triggers a
sync; `/payday` stays the place for those.

## What a run does

1. **Reads** Money Hub with GET only, from a fixed allowlist: `/api/state`, `/api/accounts`,
   `/api/budget?month=`, `/api/bills?period=`, `/api/debts`, `/api/payday?period=&check=`.
2. **Computes the facts in integer cents** (`facts.py`):
   - sync health: failing or ok, last good sync, days stale;
   - each account's balance, with its stale flag;
   - each budget category's spent, cap, remaining and % used, flagged `NEAR CAP` (85 % or more) or `OVER`;
   - unpaid bills due today through today + 6, with the check each belongs to;
   - overdue: unpaid bills due before today in the previous calendar month or this one (including
     `qtrly` occurrences), so the 1st doesn't hide last month;
   - total open debt;
   - the next payday (1st or 15th) and its unpaid-bills total.
   If Money Hub's own debt or unpaid total differs from the computed one, the entry says so. One
   failed read blanks only its own section. A code-written **headline** under the freshness line
   states the key statuses in exact figures: sync health, the over-budget and near-cap categories
   (counts and names), and the unpaid bills due in 7 days and overdue (counts, amounts, names).
3. **Optional AI summary:** one non-streaming `/api/chat` request to the broker (`assistant`,
   `think: false`, temperature 0), asking for at most 5 plain, **qualitative** sentences: no numbers
   or counts, and no bill, category or account names (the headline and tables already have them).
   - **Guard** (`guard.py`, Lead decision D3): the reply is dropped if it contains any number at all.
     That covers digits in any script (also after removing invisible characters and NFKC), spelled-out
     cardinals and ordinals, fraction and multiplier words (half, double, twice, ...), count and zero
     words (couple, few, several, both, none, nothing, nil, umpteen, ...), money words (dollar, buck,
     penny, nickel, dime, cent, quarter), inflections of all of these ("hundreds", "tenfold",
     "doubling") and Roman numerals (2+ letters in any case, or a single upper-case V X L C D M). It
     is also dropped for more than 5 sentences, counted on the raw text (`.` `!` `?` `;` `…`,
     fullwidth stops, newlines and list markers all end one). Deliberate misspellings (Cyrillic
     look-alikes, a hyphen inside a word, accents) are accepted as residual. Every figure therefore comes from code, so a model can't put a right
     number on the wrong row or flip a sign.
   - A kept summary is labelled "AI summary (local model; may be imprecise; the table is authoritative)".
   - Skips say "(did not match the figures)" for a refused reply, "(local model unavailable)" for a
     broker error or timeout, and "(no figures available)" when Money Hub gave nothing.
     The facts table is the record; the AI text is a bonus.
4. **Writes** the day's entry into `50-finance/log/YYYY-MM-01_finance-log.md` (`logfile.py`), a name
   that passes the library's `check`. It first requires the mount sentinel
   `<library_root>/.ai-library-sentinel` as a regular file (not a symlink); without it the run exits 2
   and writes nothing.
   - A new month's file gets the library header.
   - Each day sits between `<!-- finance-digest:begin/end YYYY-MM-DD -->` lines. A rerun the same day
     replaces only that block, and anything else in the file stays byte for byte.
   - Writes are atomic (temp file plus rename), refuse symlinks, and stop if the file changed meanwhile.
   - Damaged markers stop the write; the run never guesses.
   - An empty (0-byte) month file is treated as new and gets the header.
5. **Notion** (only if `notion.json` exists): the same entry as Notion blocks, sent with
   `PATCH https://api.notion.com/v1/blocks/{page_id}/children`. A Notion failure is logged and
   never fails the run.

Entry layout: the date heading; the freshness line (with ⚠ first if the sync is failing); the
facts as plain tables; the AI summary quoted as "AI summary (local model)"; then
"generated by finance-digest".

## Safety

- **Read-only.** Money Hub has no auth, so `moneyhub.py` holds the only Money Hub code:
  - a frozen path allowlist, with query parameters validated before any URL is built;
  - GET only, with no body;
  - no redirects and no proxies;
  - a 2 MB cap, and a deadline on the whole request (3 × the timeout) that also covers trickled
    headers.
- **Write methods in the source.** The tests grep for them:
  - `POST` appears only in `broker.py`, to `/api/chat`;
  - `PATCH` appears only in `notion.py`, to the constant host `api.notion.com`;
  - nothing else in the package uses a write method or opens a connection.
- **The broker URL** may not be Money Hub's address. The check compares the parsed endpoint: the
  IP normalised (IPv4-mapped unwrapped; `localhost` and every loopback address count as one) and
  the effective port (`:08710` = 8710, none = the scheme's default). It is literal-only, with no DNS.
- **Hostile text.** Text from Money Hub and from the model is cleaned the way finance-tools cleans
  it (`text.clean`, checked against it in the tests):
  - invisible, control and bidi characters are stripped;
  - `[ ] ( ) < > ! \` | @ &` become lookalikes, and links are defanged.
  - So no link, image, HTML, forged table cell or forged day marker can reach the log.
- **Secrets.** The Notion token is only read from `notion.json`, sent only in the `Authorization`
  header to `api.notion.com`, and never logged or put in an error message.

## Run

```
finance-digest [--config /etc/finance-digest/config.json] run [--date YYYY-MM-DD] [--dry-run]
```

- `--dry-run` prints the entry and writes nothing: no library and no Notion. It still asks the
  broker, so you see the real entry.
- **Exit codes:**
  - `0`: written;
  - `1`: written, but some Money Hub read failed (the entry says which);
  - `2`: nothing written (config, library, missing sentinel or log problem).
- **Logs** go to stderr.

## Config

`config.example.json` has every key. Unknown keys are refused.

| Key | Default | |
|---|---|---|
| `moneyhub_url` | (required) | `http(s)://host:port` |
| `broker_url` | (required if `ai_summary`) | the broker, never Money Hub's address |
| `library_root` | `/srv/ai-library` | an initialised AI Library |
| `timezone` | `America/New_York` | sets "today", the budget month and the next check |
| `ai_summary` | `true` | |
| `model` | `assistant` | |
| `moneyhub_timeout_s` | `10` | per read; the whole request is capped at 3 × this |
| `broker_timeout_s` | `120` | the whole chat request |
| `notion_file` | `/etc/finance-digest/notion.json` | `{"token": "...", "page_id": "..."}`; absent = Notion off |
| `notion_timeout_s` | `20` | |
| `bills_window_days` | `7` | 1 to 28 |

## Tests

```
cd apps/finance-digest
python3 -m unittest
```

The tests use only the standard library. They start a fake Money Hub, a fake broker and a fake
Notion on 127.0.0.1 (`tests/fakes.py`) and use temporary libraries. Nothing reaches a real network.
Every name, amount and date in `tests/` is invented (year 2030). Never paste real Money Hub output
into a fixture.
